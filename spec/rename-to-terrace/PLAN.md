# PLAN — Rename `sosfs` to Terrace

> **Status:** Draft for review · **Last updated:** 2026-11-12
> **Authoritative technical design.** The *how*. Vision/contract is [`GOAL.md`](GOAL.md);
> the phased executable roadmap is [`TECH.md`](TECH.md). This plan ran lean (`skip research`), so
> there is no `research/` folder: the GOAL carries the census, and the plan's own reads and a
> prototype of the whole rename stand in for briefs. Every design element traces to a GOAL R-ID.

## 1. Summary

The rename is a scripted, ordered substitution plus one `git mv`, run in three phases. The builder
executes rules and reviews a diff; nobody hand-edits 116 files. [`rename.py`](rename.py) is the
executable form of the rules below and a record of how the change was made, not part of the product.
Phase 1 moves the package, the distribution and every identifier and leaves the suite green at 731.
Phase 2 moves the names the product writes to disk, reads from the environment and serves as
attributes, and proves each with a drive. Phase 3 moves the documents, writes the `CHANGELOG.md`
entry and runs the census. The whole rename was run on a prototype tree before this plan was
committed, and each phase's gate was run on that phase's own tree.

## 2. Design

### Scopes

- **Code scope:** tracked files under `src/`, `tests/` and `tools/`, plus `pyproject.toml`,
  `docker-compose.yml` and `.github/workflows/ci.yml`. `uv.lock` is regenerated by `uv lock`, never
  substituted.
- **Document scope:** `AGENTS.md`, `PLAN.md`, `README.md`, `ROADMAP.md` and every `issues/*.md`
  except this cycle's own seed. `CLAUDE.md` is a symbolic link and is skipped.
- **Never touched:** the root `GOAL.md`, everything under `spec/`, and
  `issues/rename-to-terrace.md`.

### The rules, in the order they apply

| # | Rule | From | To |
|---|---|---|---|
| 0 | Move | `src/sosfs/` | `src/terrace/` (`git mv`, phase 1 only) |
| 1 | Hand-written sites | an exact string, once per file | the listed replacement |
| 2 | Class names | `SOSFSApp`, `SOSFSError` | `TerraceApp`, `TerraceError` |
| 3 | Upper case | `SOSFS` | `TERRACE` |
| 4 | Lower case | `sosfs` | `terrace` |
| 5 | Prose phrase | `simple-overlay-service`; `Simple [Oo]verlay [Ss]ervice` | `terrace`; `Terrace` |
| 6 | Comment columns | trailing comments that shared a column | still share one |
| 7 | After the rules | an exact string the rules produced | the listed correction |
| 8 | Dated notes | — | appended to two seeds (phase 3 only) |

Rule 2 runs before rule 3 and rule 3 before rule 4, so no rule can produce the collapsed form
`TERRACE` followed by a letter. Rule 1 runs first because its sites are matched against the text as
the base commit holds it. Rules 2 to 5 are plain replacements with no word-boundary test: the GOAL
measured that `sos` occurs nowhere outside the old name.

Rule 6 is layout only. Where consecutive lines carry trailing comments at one column, the comments
keep one column: the old one if every line still fits with two spaces before the comment, else the
least column that does. A ruled comment line (one ending in a run of dashes) keeps its width. The
rules never add or remove a line in a file under `src/`, `tests/` or `tools/`, so every `file:line`
anchor in the seeds and in `AGENTS.md` still resolves. Prose is not reflowed: a line in a Markdown
file that grows past its wrap column stays as the substitution left it.

### Which rules run in which phase

| Phase | Scope | Rules | Held back |
|---|---|---|---|
| P1 | code | 0, 1, 2, 4, 5, 6 | rule 3 entirely, and the contract forms of rule 4 |
| P2 | code | 1, 3, 4, 6 | nothing |
| P3 | documents | 1, 2, 3, 4, 5, 6, 7, 8 | nothing |

The **contract forms** P1 holds back for P2 are the lower-case spellings that are written to a tier
root, form a path, or name an attribute:

- `.sosfs` where no identifier character precedes the dot: the marker directory, the partial
  directory, the S3 sentinel `.sosfs.keep` and the local file `.sosfs.toml`, in code, docstrings and
  test oracles alike;
- `user.sosfs.`, the attribute namespace;
- the quoted path component `'sosfs'` in `src/terrace/core/platform.py`, eight occurrences;
- `<state>/sosfs/log` in the header comment of `tools/temp_site.sh`;
- the first line of the marker file, `# sosfs managed-location marker`, in `state/lifecycle.py`.

P1 and P2 stay separate phases. The tree between them is mixed (the package is `terrace`, a tier
root still holds the old marker directory, the prefix is still the old one) and it is green: every
held form moves as a token class, so a constant and the docstrings, guards and test oracles that
spell the same literal move in the same phase. The prototype's P1 tree passes lint and 731 unit
tests. The review grades the squashed diff, so the mixed tree costs a reviewer nothing, and it buys
a verdict per kind of change: a red P1 is an identity fault, a red P2 is a contract fault.

### Hand-written sites (rule 1)

The sites a blanket rule gets wrong, or that need a sentence a person wrote. `rename.py` holds the

## 3. Invariant gate (AGENTS.md constitution check)

Walked before the design and again after it. The rename passes textually through every file on the
high-blast-radius list; `skip research` overrode the fan-out that would follow, by the foreman's
ruling. The gate script is a gate-shaped deliverable, so the adversarial design review ran (section 4).

- **§ 1 Write ordering, § 5 Committed source path, § 6 Write-back, § 7 Eviction, § 10 Concurrency,
  § 11 Engine API** — no statement moves. In these files the rules change import lines, base-class
  names, docstrings, three thread names and one lazy import. The suite at 731 and the line-count
  check are the evidence.
- **§ 2 State-store durability** — `SCHEMA_VERSION` stays 2 and `db.py` changes in imports,
  base-class names, two docstrings and the `resources.files` argument. A state database written by
  the base commit opens under the renamed code.
- **§ 3 SQL construction** — the renderer's dotted name changes in `AGENTS.md`; `sql.py` changes in
  one base-class name.
- **§ 4 Tier atomicity** — the temp still lands under the partial directory and the journal still
  classifies by the first two path components. Both literals move in the same phase. The marker
  tree still reads as absent and refuses mutation on every tier: the guards compare against
  `MARKER_DIR`, and the tests that spell the literal move with it.
- **§ 8 Lifecycle** — "a marker is never rewritten for an already-registered tier" is what makes R5
  hold, and is not edited.
- **§ 9 Layering** — `tools/lint.sh` asserts it with a `grep` for the package name over three
  directories. Left behind, the assertion would search directories that no longer exist and report
  OK. It moves in P1 with the package, and the gate checks that `lint.sh` is the base file with the
  name changed and nothing else.
- **§ Conventions** — version stays single-sourced; no spec id enters `src/`, `tests/` or
  `README.md`; `AGENTS.md` moves in the same landing commit as the code it describes. Between P1 and
  P3 `AGENTS.md` describes paths that have moved. That is a state of the cycle branch only: the
  profile rows the factory reads during the build (`verify`, `setup`, the throwaway environment)
  name no package.
- **§ Known open violations** — two rows name commands; rule 4 renames them. None is fixed here.

## 4. Rabbit holes (resolved)

- **Can the tree be green between the package move and the contract move?** Yes. Measured on the
  prototype: after P1 alone, lint passes and the unit lane reports 731 passed.
- **Does the refusal in R5 need a real mount?** No. `terrace mount <spec> <mountpoint> -f` reaches
  the engine's attach before anything loads libfuse. Against an overlay written by the base commit's
  own code it exits 5 with `Tier 'project' marker is missing — audit required`, and both tier roots
  compare equal before and after by name, size and SHA-256. The gate drives the CLI.
- **How does a gate run the base commit's code?** From `git archive` of the base commit, put first
  on `sys.path` in a child process, with `importlib.metadata.version` stubbed because that tree is
  not installed. The dependencies are the locked set, which the rename does not change.
- **Does `uv lock` change anything but the name?** No. The project's own entry moves in the file's
  alphabetical order; parsed, the package lists are equal once the base entry is renamed.
- **A stale distribution can hide a missed literal.** `uv run` does not remove an old editable
  install, so `get_version` with the old name would still resolve. The gate syncs exactly and then
  checks the environment holds no old distribution, no old module and no `src/sosfs` directory.
- **Stale bytecode can flip a verdict.** A source edited and restored within one second, at the same
  size, keeps its old `.pyc`. This bit the plan's own mutant loop: a restored `db.py` went on
  reporting schema version 3. The gate now gives each run its own bytecode directory.
- **Line length.** No line under `src/` or `tests/` crosses 120 columns: the three that exceed it do
  so at the base commit and hold no name.
- **Thread names.** `terrace-writeback` is 17 characters and Linux keeps 15 of a thread's name.
  CPython truncates; nothing asserts a thread name. Cosmetic.

**Dry runs.** Each on the prototype tree for that phase, with the plan's own `ROADMAP.md` and seed
edits in place:

| Tree | Mode(s) | Result |
|---|---|---|
| plan commit, nothing renamed | `identity` | red at the first check |
| after P1 | `identity suite` | green, 731 passed |
| after P1 | `contracts`; `census` | red (103 old-name lines in the code scope; 470 in the census) |
| after P2 | `contracts suite`; `identity` | green, 731 passed |
| after P2 | `census` | red (367 lines) |
| after P3 | `census docs ledger identity contracts suite` | green, 731 passed |
| after P3, `rename.py p3` run again | — | every site reports already applied; the tree is unchanged |

`docs` and `ledger` read this file and `TECH.md`, and were run on the P3 tree once both existed. The

**Mutants.** Twenty-three single edits were planted on the P3 tree of the first replay, each staged

`PARTIAL_DIR`, a misspelt `MARKER_DIR`, sentinel, attribute name, provenance string, configuration
variable and path component, each of the three scrubs, the MinIO variable, a schema default, a

## 5. Risks & open questions

**For the sign-off.**

1. **This cycle's own `ROADMAP.md` entry** (first deviation row). The plan rewords three phrases so
   R1 holds. If the entry must stay byte for byte, R1 needs an exception for it in the GOAL; if it
   should go, P3 can remove it.
2. **R6, a name that begins with the prefix's letters and no underscore** (second deviation row).
   Pre-existing. The plan records it as a dated note in `issues/config-command.md` and does not
   change it. Ruling the one-line filter into scope would make R6 hold as worded.
3. **Two dated notes, not two new seeds.** The plan's drives measured two behaviours this cycle
   leaves alone, and P3 appends each to the seed that owns the area: the prefix match above, and a
   refused attach that leaves `shutdown_state` at `mounted` (`issues/audit-command.md`). After the
   refusal R5 describes, a second mount attempt stops at the crash gate and never reaches the
   marker. Both hold at the base commit. A seed of its own for either is a foreman's call.

**Risks.**

- **Branches cut before this lands.** Two other cycle worktrees are open on the base commit. Each
  will conflict with the package move when it rebases, and any line it adds under the old name comes
  back with it. R1 is a statement about this cycle's final commit.
- **Anchors that cite a commit.** A seed that names a path beside a hash from before the rename now
  names the path as it is today. `git show <hash>:<path>` needs the old directory; `CHANGELOG.md`
  records the move.
- **The gate needs libfuse and the S3 test stack.** `contracts` and `suite` exit 3, could not run,
  on a host where `mfusepy` cannot load libfuse, and `contracts` does where `moto` is absent. Neither
  reads that as green or as red.
- **CI is not part of any phase gate.** The four jobs run when the foreman pushes. `uv sync --locked`
  there depends on the regenerated lock, which `identity` checks with `uv lock --check`.

**Review.** One reviewer pass, six findings, all folded before this plan was committed.

- *A good tree read red without libfuse, and the exit code the plan promised was unreachable.* With
  libfuse hidden, `contracts` went red on a skipped adapter test and `suite` on 44 skips. Both modes
  now probe `import mfusepy` first and exit 3.
- *`identity` graded the working copy.* A staged old name with a good working file passed. Every
  mode now refuses a tree with unstaged edits, not only `contracts` and `census`.
- *`docs` matched the `CHANGELOG.md` entry by loose substrings.* An entry with the console-script
  pair dropped, and one with the sentinel pair reversed, both passed. Each pair must now sit in one
  bullet, old name before the arrow and new name after it. Both mutants go red.
- *The default per-user log path was in neither the entry nor the list.* Added to both.
- *`rename.py` reported a deletion site that never matched as already removed.* It now fails while
  the notice's first line is still in the file.
- *A dry run skipped the sites applied after the rules without saying so.* It says so.

The reviewer found nothing in the comment-column rule (18 lines touched, all trailing comments, and
one ruled comment), no old phrase wrapped across a line break, no sentence made false in a seed
beyond those listed in section 2, and no stray form hidden by the contract-form check on the P1 tree.

## 6. Verification strategy

One gate script, [`verify/rename_gate.py`](verify/rename_gate.py), with a mode per concern. Its
header states the modes, footprint and exit codes. Run from the worktree root:

```
uv run --no-project --python 3.15 python -I spec/rename-to-terrace/verify/rename_gate.py MODE [MODE ...]
```

- `identity` (R2, R3): the moved tree, no collapsed identifier, only contract forms left in the code
  scope, line counts kept, `lint.sh` intact, `uv lock --check`, the lock equal to the base but for
  the name, an environment with `terrace` and no old distribution, `--version` twice and `--help`
  under `tools/temp_site.sh`, and a build into an empty directory: one sdist, one wheel, the name and
  URL in the wheel's metadata.
- `contracts` (R4 to R9): no old name in the code scope, then drives in child processes. A fresh
  overlay shows `.terrace/marker` in each root and a transfer temporary moved out of
  `.terrace/partial/`. An S3 tier on a moto server shows one `.terrace.keep` object. Eleven named unit
  tests grade the managed tree on the three tiers and the attribute names. An overlay written by the
  base commit's code is opened at the database (no `SchemaMismatch`) and then refused through the
  CLI, with both tier roots compared before and after. The configuration is read under
  `tools/temp_site.sh` with the new prefix, the new file variable, the old spellings and no variable.
  The three scrubs are each exercised, the test helper's with a malformed configuration file that
  stops the CLI when it leaks. The path namespace is read with the XDG variables set and unset. The
  adapter serves the two attributes and raises `ENOATTR` for six other names, the old ones among
  them. The mode prints that the real-mount check was not run.
- `census` (R1): the GOAL's three commands, on a tree with nothing unstaged.
- `docs` (R11, R8's record): the `CHANGELOG.md` entry against a list of eighteen pairs, each in one
  bullet with the old name before the arrow and the new one after it, the
  `PLAN.md` row, `AGENTS.md`, and the sentence in section 2 of this file.
- `ledger`: each deferral in `TECH.md`'s phase bodies names a seed that exists and that `ROADMAP.md`
  lists.
- `suite` (R10): `tools/lint.sh` exits 0 and the unit lane's JUnit report holds 731 passed, 0 failed,
  0 errors, 0 skipped. The count is the base commit's, measured by the foreman on this host.
- `prepush`: a clean tree, no home-directory path in the branch's diff or messages, then `census`.

A phase stages its change before it runs its gate: every mode refuses a tree whose tracked files
differ from the index, so what is graded is what will be committed. No test is added. The GOAL's rule for a
behaviour with no unit test today is a drive from outside `tests/`, and the drives live in the gate,
under `spec/`, where the old name may be spelt.

The R-IDs graded from this cycle's own records are R8's statement that the real-mount check was not
run (this file) and R11's `CHANGELOG.md`, `PLAN.md` and `AGENTS.md` text. A blind reviewer does not
see `spec/`, so the first is the orchestrator's to grade.
